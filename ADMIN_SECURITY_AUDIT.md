# Phase 3 security audit

Reviewed 19–20 October 2026 against isolated staging `iitblbdqztuxdzpaetie` and the real local migrations. All 37 public application tables have RLS. The hosted security advisor found no new database/RLS issue; its existing Auth leaked-password-protection warning remains. [Remediation reference](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

Implemented/retained boundaries: server-verified Supabase identity, trusted `user_roles`, AAL2 at page/API/database layers, lightweight Proxy entry redirects, explicit RLS/grants, private security-definer implementations with fixed empty search paths, public invoker wrappers, no browser secret key, same-origin cookie mutations, strict product/order/analytics schemas, bounded body/upload parsing, rate limits, rich-text sanitization, parameterized database calls and safe errors. Last-owner protection remains enforced.

Actual defects addressed: archived Place deletion omitted itinerary/portfolio/recommendation references; stale Place/product saves lacked a consistent editor guard; inventory confirmation could otherwise be overwritten by an older catalog editor; the public viewer RPC needed compatible predicate execution grants after introducing order-manager access. Regression tests cover each relevant boundary. Stock confirmation now follows parent-before-variant lock ordering.

The final media review also found that legacy media cleanup did not inspect new JSON product galleries. Database triggers now protect those references from revocation/deletion and lock public media during product saves, closing the cleanup/association race. Trigger helpers are private, use an empty search path and are not callable by browser roles.

Commerce tables deny ordinary direct writes, including Owner browser writes. Payment and refund reconciliation is service-only, amount/reference validated, event-idempotent and never an admin toggle. Checkout remains disabled. Audit summaries whitelist safe changed fields and omit passwords, tokens, private notes and full payment payloads. Uploads decode/re-encode allowed images, use random paths, reject oversize input and retain existing deletion/reference safeguards.

Pending external assurance: real provider/Sandbox end-to-end acceptance and merch webhook adapter, production payment authorization, mail delivery configuration, leaked-password setting, production deployment/configuration and operational security review. Physical-device/screen-reader/cross-engine checks are not implied by Chrome automation. Detailed executed results are in ADMIN_TEST_RESULTS.md.

The performance advisor retains earlier informational notices for the composite itinerary FK and the polymorphic taxonomy/media mapping, plus overlapping permissive read/write policies and unused-index statistics. Those policies intentionally combine public/self access with MFA staff access; the executed RLS matrix remains the authorization evidence. The new gallery-reference GIN index is also reported unused on the four-product staging dataset, where the planner can prefer a sequential scan. These are disclosed tuning/maintenance notices, not new authorization bypasses. References: [foreign-key indexing](https://supabase.com/docs/guides/database/database-linter?lint=0001_unindexed_foreign_keys), [primary keys](https://supabase.com/docs/guides/database/database-linter?lint=0004_no_primary_key), [index usage](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index), [permissive-policy consolidation](https://supabase.com/docs/guides/database/database-linter?lint=0006_multiple_permissive_policies). No unrelated policy rewrite or index deletion was made from staging-only statistics.
